# P1 vector-renderer-equivalence corpus

Fixture corpus for `03-render-color-pipeline.md` §2.6's golden-output safety
net — the P1 merge gate ("Renderer rework destabilizes vector editing",
`00-overview.md` §7). Exercised by
`crates/photonic-render/tests/golden_vector_equivalence.rs`.

**Not** the same system as the repo-root `tests/golden/` (video/timeline
golden-frame corpus, `11-testing-phasing.md` §1). That corpus renders
timeline sequences through the frame-graph IR at sampled ticks. This corpus
renders single static `.photon` documents through
`HeadlessRenderer::render_rgba_with_opts` — the *existing* vector renderer,
pre- vs post-P1-refactor. Different scope, different lifecycle. Do not merge
them (both docs carry this note).

## Layout

```
{case-name}/
  project.photon        # a small hand-authored .photon document
  expected/
    reference.png        # blessed reference render (byte-for-byte or PSNR
                          # target per the comparison rule below)
  tolerance_db.txt        # OPTIONAL — presence switches this case from
                          # byte-exact to PSNR->=N dB comparison (see below)
```

## Comparison rule

- **No `tolerance_db.txt`**: byte-exact RGBA comparison. Correct for every
  case whose render path P1 is not supposed to change at all (dirty
  tracking / persistent buffers / f16 texture plumbing are pure perf
  refactors — 03 §2.6: "must not alter output at all").
- **`tolerance_db.txt` present**: contents are a single float, the minimum
  acceptable PSNR in dB. Use this only for cases that exercise
  `COMPOSITE_SHADER` wiring (03 §2.4) — isolation-pass compositing can shift
  sub-LSB rounding vs. the fixed-function path it replaces for previously
  on-canvas-approximated modes (Hue/Saturation/Color/Luminosity and other
  backdrop-read modes). `blend_nonseparable/` carries `45.0`, matching 03
  §2.6's recommended threshold.

## Regenerating fixtures

`project.photon` files are generated by
`crates/photonic-render/examples/gen_p1_golden_fixtures.rs` (a checked-in
dev tool, not run by CI — same convention as `tools/gen-mcp-docs.py`):

```sh
cargo run -p photonic-render --example gen_p1_golden_fixtures
```

## Blessing reference images

`expected/reference.png` files are written by the test harness itself in
bless mode:

```sh
PHOTONIC_BLESS_GOLDEN=1 cargo test -p photonic-render --test golden_vector_equivalence -- --test-threads=1
```

Every bless run must be a reviewed diff (`git diff --stat tests/golden/`)
before commit — a human confirms the new/changed PNGs are the *intended*
pixels, same review bar as any other test-baseline change. Never automatic
in CI.

## Case inventory

| Case | Exercises |
|---|---|
| `paths_fills_basic` | Plain solid-fill paths (rect + ellipse), the tessellate-and-fill baseline |
| `strokes_basic` | Stroke-only paths: round cap/join, square cap + dash array |
| `gradient_linear` | 3-stop linear gradient fill |
| `gradient_radial` | 3-stop radial gradient fill |
| `blend_separable` | Fixed-function blend modes (`Multiply`/`Screen`/`Darken`/`Lighten`) — byte-exact |
| `blend_nonseparable` | `COMPOSITE_SHADER`-path modes (`Hue`/`Saturation`/`Color`/`Luminosity`) — PSNR-tolerant |
| `text_basic` | A glyphon-rendered text node |
| `raster_placement` | A placed + scaled raster node |
| `effect_stack_color_overlay_stroke` | Layer-Styles effect stack (`ColorOverlay` + `StrokeEffect`), no own fill/stroke |
| `boolean_groups` | Live (non-destructive) boolean union (#25) rendered as its single resolved path |

Budget: this corpus + `tests/golden/` fixtures must stay well under the
10 MB standing budget (`11-testing-phasing.md` §1.5); ten ~120×120 PNGs is a
few hundred KB total.
